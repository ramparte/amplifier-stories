01 / The gap

The tools exist. The starting point is missing.

Upstream Smart Tools already live in different repositories. A coding host still needs one reliable place to learn what is available before it goes hunting through remote docs.

S1 · S3
01

Scattered sources

Tool manifests and usage guidance stay with the upstream tool. Discovery starts in a different place every time.

02

Repeated remote reads

Before a host can choose a tool, it may need to fetch several descriptions just to understand the options.

03

Too much implied power

A catalog should help a host find and assess a tool. It should not quietly install, configure credentials, or bypass permission.

TargetMake discovery boring. Point to the source, keep an exact local snapshot, then read the selected tool's own guidance only when needed.

02 / The product

One skill. One catalog. Exact snapshots.

The catalog stays small. It stores source pointers under a predictable path. Maintenance turns those pointers into generated documentation and provenance that a discovery skill can verify first.

S1 · S2 · S4
01 / POINT

Source pointer

tools/<slug>/source.json

Credential-free HTTPS repository URL. Ref defaults to main; path defaults to ..

02 / REFRESH

Resolve once

repository + ref

The refresh job resolves a shared repository and ref once per run, then follows each path.

03 / SNAPSHOT

Write the pair

SMART_TOOL.md + provenance.json

The snapshot preserves the exact upstream document with its commit, path, and last successful refresh.

04 / DISCOVER

Start local

verify -> select -> read

The shared skill checks snapshots and provenance before going upstream for selected documentation.

Kept out of scopeThe catalog does not install tools, configure providers, grant credentials, or execute upstream code.

Discovery is five moves.

The skill is a short path from inventory to informed action. It does not pretend that listing a tool proves it is installed, usable, or appropriate for the current task.

05 / The maintenance loop

Descriptions refreshed automatically. Source and revision stay visible.

GitHub Actions keeps generated snapshots current without moving upstream execution into the catalog.

S1 · S4

Refresh triggers

  • After source, refresh script, or workflow changes reach main.
  • On a daily schedule.
  • On manual dispatch.

What the job does

01Read each pointer and resolve the source.
02Fetch the exact SMART_TOOL.md.
03Write the snapshot and provenance pair.
On failure, keep the last-good pair.

If a source cannot refresh, the prior snapshot and provenance stay in place and the failure is visible in workflow logs.

Safety boundary

The workflow fetches documentation. It does not run upstream code.

What this deck does not claim

No universal host test, performance baseline, savings number, automatic installer, credential setup, permission bypass, or upstream code execution. The revised snapshot-first flow has not been cross-host reverified.

The catalog makes discovery easier to start. It does not turn a listed tool into an installed or usable tool by itself.
