How It Works

An observer is just markdown
with YAML frontmatter

Defined exactly like an agent — but instead of doing the work, it watches the work and reports back.

---
observer:
  name: Security Auditor
  description: Identifies security vulnerabilities
  model: claude-3-5-haiku-latest
  timeout: 30

tools:
  - grep
  - read_file
---

# Security Auditor

You are a security expert reviewing code...
Look for SQL injection, XSS, hardcoded secrets...

Architecture

Three modules make it run

hooks-observations
Orchestrates observers via lifecycle hooks. Triggers on file changes and conversation events.
tool-observations
CRUD operations for observation management. Create, read, update, delete observations.
hooks-observations-display
Optional visualization module. Surfaces active observations in the conversation.
Keeping the Signal Clean

Dedup and auto-resolution
stop the noise

~50 observers watching at once could bury you. Two pivots keep the stream useful.

Semantic deduplication — the same issue reported by multiple observers is collapsed via LLM-based similarity detection, so you see it once.
Auto-resolution — observers automatically close issues once the underlying problem is fixed. No stale observations linger.
