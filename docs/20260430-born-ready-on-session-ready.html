The Problem

Modules used to mount in the dark — so cross-module code had to guess

When a module's mount() runs, the coordinator is only partially assembled. Each phase finishes before the next begins, and after phase 5 the initializer simply returns — no "all-modules-ready" signal.

Phase 1 Orchestrator — coordinator is empty Phase 2 Context — sees orchestrator only Phase 3 Providers — sees orch + context Phase 4 Tools — sees orch + context + all providers Phase 5 Hooks — sees everything EXCEPT later hooks [return] — no "done" signal

A hook that wanted to know whether a tool was mounted had to defend against both orderings. The result was a recurring defensive pattern tax:

Defensive patternInstances
Dual-path init4

The worst case: tool-delegate registered its 5 delegation events with register_capability() instead of register_contributor(), so collect_contributions() never saw them. The entire delegation tree was absent from the graph — a 7% coverage gap, silent for months.
The Solution

One function, one guarantee: do cross-module work after everything is mounted

async def on_session_ready(coordinator) -> None:
    """Called after ALL modules have completed
    their mount() calls. The coordinator is
    fully composed. Return value is ignored.
    Exceptions are non-fatal and isolated.
    """
    # Tools are here. Providers are here.
    # Every hook is here. No guessing.
    contributions = await coordinator
        .collect_contributions("obs.events")
Auto-discovered by the loader via the __on_session_ready__ attribute — no new entry point needed. mount() now only stores config.

Design Decisions

  • coordinator only, no config — config belongs in mount()
  • async-only — sync implementations log a warning, are skipped
  • non-fatal, isolated — one failure cannot block others
  • fires before session:fork — children run independently
  • 100% backward compatible — existing modules unchanged
  • queue drains after dispatch — no double-dispatch risk

Enqueue happens after each successful mount() — failed mounts never get a Phase 6 callback. Failures self-report on the event bus.

First Adopter · hooks-logging

The logging hook adopted it first — and mount() shrank to one line

Before — race-prone work inside mount()
async def mount(coordinator, config=None):
    config = config or {}
    session_logger = SessionLogger(...)
    async def handler(event, data):
        session_logger.write(...)
    events = list(ALL_EVENTS)
    if auto_discover:
        # race: tools may not be mounted yet
        discovered = coordinator.get_capability(
            "observability.events") or []
        events.extend(discovered)
    for ev in events:
        coordinator.hooks.register(ev, handler)
After — defer in mount(), wire in Phase 6
_deferred_configs: list[dict] = []

async def mount(coordinator, config=None):
    _deferred_configs.append(config or {})

async def on_session_ready(coordinator):
    while _deferred_configs:
        config = _deferred_configs.pop(0)
        # safe here — all tools mounted
        contributions = await coordinator
            .collect_contributions("obs.events")
        for c in contributions:
            events.extend(c)
        for ev in events:
            coordinator.hooks.register(ev, handler)

The Pattern To Keep

mount() stores config; on_session_ready() does the cross-module work

The Pattern

  • mount() — store config only
  • on_session_ready() — do cross-module work
  • collect_contributions() — safe only here
  • DTU e2e profile — prove the full stack
Next: the context-intelligence hook drops its dual-path init using this same pattern. Any module that registers events or reads capabilities in mount() should migrate.
