The Problem

7,000 tokens
before you said hello

V1 loaded four context files into every session just to teach the AI how its own memory works. The instructions were longer than most conversations.

📜

738 Lines of Instructions

Four files — delegation rules, auto-context, writer instructions, a system guide — loaded at session start, every time.

💸

~7,000 Tokens Burned

Before the user typed a word, the memory system had already eaten 7K tokens of the context window. And it grew as memory grew.

🔃

Said Four Times Over

The same “never read memory-store.yaml directly” warning appeared in four different files. The AI got the message — redundantly.

The memory system's instructions about being token-efficient were themselves the biggest source of token waste.

The Reframe

Stop teaching what
the model already knows

V1 spent hundreds of tokens explaining YAML formatting, bash appends, and pattern matching — things a modern LLM already understands. V2 asked a different question and just stated the contract.

V1: Teach Everything

  • Full bash examples for append operations
  • YAML templates and formatting rules
  • “Don't do this” counter-examples
  • Self-check rubrics and decision trees
  • Keyword lists and error procedures

V2: State the Contract

  • Three operations, three rules
  • Writes: append to the file, never load it
  • Reads: delegate to a sub-agent, always
  • Work status: read the small file directly
  • 37 lines. Trust the LLM. Done.

The best context is the minimum context that produces correct behavior. Everything else is overhead. — one commit, 69c3629, swapped 4 includes for 1.

Architecture

A sub-agent absorbs the load so the session stays lean

Memory reads go to a sub-agent. It absorbs the token cost of loading large files and returns only the matches. The main session never sees the bulk.

W

Writes: Main Agent, Append-Only

cat >> memory-store.yaml — read the last few lines for the next ID, append the entry. Never load the full file. Cost: ~100 tokens

R

Reads: Delegated to Sub-Agent

The memory-retrieval agent loads the full store in its own isolated context, searches, and returns only 2–3 matching entries. Cost in the main session: ~200 tokens

S

Work Status: Direct Read

work-log.yaml is a small file (~500 tokens). Safe to read directly — no delegation needed.

The sub-agent is a “context sink” — it absorbs 10,000+ tokens of memory data, but only ~200 tokens flow back. When it finishes, its context is cleared. That's why cost stays flat.

Deep Dive

Memory as an index, not storage

To scale past a flat YAML file, V2's design replaces it with three layers — each loaded only when needed, each cheaper than the last.

L0

MEMORY.md — The Index (always loaded)

~200 lines max, hard-capped. One-liner summaries with pointers to topic files. The only file the retrieval agent always reads.

L1

topics/*.md — Topic Files (on-demand)

5–50 entries per theme, free-form markdown. Opened only when a search hits the relevant index line. The unit of consolidation.

L2

Session Transcripts — Layer 2 (never loaded)

Amplifier's existing session logs. Searched via session-analyst delegation only when Layers 0 and 1 don't have the answer.

The 200-line index cap is enforced by consolidation: grow past it and pruning must run. A vector-search seam activates only when smoke tests show retrieval misses at ~50+ topic files — not before.

V2 Design Spec

Beyond compression, memory maintains itself

Loading less is only step one. The V2 design spec (April 2026, 342 lines) keeps the store clean so it never re-bloats the context it just trimmed.

Self-maintaining by design

  • autoDream — a background agent merges, dedups, and prunes stale entries, resolving contradictions
  • Derivability rule — “if you can grep for it, don't remember it.” Store only non-derivable knowledge
  • Temporal tags — [temporal:DATE] and [persistent] make staleness a first-class concept
  • Contradiction check — new memories are checked against the index; conflicts surface to the user before storing
  • Git safety net — pre/post-consolidation commits; if autoDream corrupts data, git revert restores it

The Principle

Less context,
more memory

The counter-intuitive lesson: a memory system got radically better by loading less. State the minimum contract, delegate the heavy lifting, and let the model do what it already knows how to do.

The best context is the minimum context that produces correct behavior — everything else is overhead you pay for on every single session.
