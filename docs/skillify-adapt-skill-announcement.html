The Problem

A perfected workflow
dies when the session ends.

🔁

The knowledge evaporates

You spend 45 minutes perfecting a complex multi-step process. Next week you need it again — but it lived only in that session.

📦

Foreign skills don't fit

Battle-tested skills from Claude Code or Cursor use different tool names, paths, and frontmatter than Amplifier expects.

Until now, the only fix was to hand-author SKILL.md files from scratch — knowing the full Agent Skills spec, Amplifier's extensions, and conventions scattered across many docs.

The Payoff

It's skills all the way down.

Step 1 — Build /skillify

We brainstormed the design section by section, iterating until the skill worked end to end.

Step 2 — Adapt a foreign skill by hand

We walked through porting a Claude Code skill to Amplifier, working out the mapping rules live.

Step 3 — Run /skillify on that very process

We literally used /skillify to capture the adaptation workflow we'd just performed.

Step 4 — /adapt-skill was born

That capture became /adapt-skill — proof the capture loop turns a one-off workflow into a durable skill.

Now let's see how each command does it. 🐢

/skillify

Six steps turn a finished session into a tested skill.

1Consult Skills-Assist
→
2Analyze Session
→
3Interview User
→
4Write SKILL.md
→
5Test
→
6Review & Save
  • Adaptive interview — calibrates depth to complexity. A 2-step process gets 1–2 rounds; a complex workflow gets the full treatment.
  • Tests locally before saving — verifies the skill via load_skill() to catch issues before you commit.
  • Captures intent, not just actions — the interview surfaces the "why" behind each step so the skill generalizes.

Invoke with /skillify — or just say "save this as a skill."

/adapt-skill

It rewrites a foreign skill into Amplifier's dialect.

An 8-step workflow — platform research, convention mapping, writing, and a full self-test — translates skills from Claude Code, Cursor, or any AI assistant.

🔀

Auto-maps conventions

Tool names (Read → read_file), paths (.claude/ → .amplifier/), frontmatter — all handled.

🔍

Researches unknowns

Hits an unfamiliar convention? It reads the source platform's docs before guessing.

🧪

Self-tests via delegate

Spawns a delegate self-session to exercise the adapted skill — verifying it works in Amplifier.

Invoke with /adapt-skill path/to/source.md — or "port this skill to Amplifier."

The Pattern That Keeps Them Honest

Both skills defer to one living reference
instead of hardcoding conventions.

  • Both start with Step 1: load_skill("skills-assist")
  • Rather than baking in Amplifier conventions, they read the living spec
  • When the spec evolves, the skills pick up the latest automatically
  • The recommended pattern for any skill that generates or validates other skills
