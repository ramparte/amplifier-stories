Every Live Bundle Link Already 404s

On the production withamplifier.com site, all 12 community bundle links are broken. Content drift isn't a hypothetical risk here — it already happened.

And nobody noticed until we went looking. So how did the site's content get this way?
The Site

withamplifier.com Is Hand-Copied From Docs

The public site is built from 8 data-sections — each one populated by copying text out of source docs like README.md, MODULES.md, and USER_ONBOARDING.md.

Copy once, and the copy is frozen while the sources keep moving. That gap is where the 404s came from.
The Disease

Copied Content Drifts, Silently

The broken links are one symptom of a single root cause: nothing keeps the site tied to its sources.

Manual Updates Go Stale
Content is copied from docs, edited, and quickly diverges as the source files keep evolving underneath it.
No Traceability
When content is wrong, there's no way to know which source file was supposed to be the authority.
Failures Stay Silent
Broken links, outdated commands, and wrong module names go undetected until a user complains — exactly like the 12 dead links.
The Turn

Stop Copying.
Generate From Source.

If drift comes from hand-copying, remove the copy. Every section on the site is produced directly from its authoritative source file — so the site and its sources can never disagree.

That single decision is what makes drift structurally impossible. Here's what it produces.

How: Traceability

Every Element Names Its Source

The mapping is the contract: each web element declares the exact source file it comes from and how it must be verified.

// withamplifier-content.json { "section": "quick-install", "web_element": "data-section='quick-install'", "source_files": ["README.md#installation"], "accuracy": "verbatim", "validation": { "priority": "critical", "checks": ["command_syntax", "url_validity"] } }
