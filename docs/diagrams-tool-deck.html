The Gap

Agents can tell,
but they can’t show

An agent can describe an architecture in a paragraph — but a picture lands faster. The catch: standing up a real diagram renderer usually means installing GraphViz or running a PlantUML server, dependencies nobody wants in their stack.

So agents default to walls of text where a diagram would do. The visual channel goes unused — not for lack of ideas, but for lack of a renderer.
The Enabler

Meet Kroki: describe a diagram, get a picture

Kroki is a rendering service that turns text diagram definitions into images. The tool never renders anything itself — it just speaks to Kroki over HTTP.

Kroki.io API
No GraphViz install. No PlantUML server. No local rendering engine. Just HTTP requests to Kroki's free public API, which returns SVG or PNG.
Self-hosted ready
Point to your own Kroki instance for air-gapped or enterprise deployments. Same API, full control — the tool doesn't change.
Agents write diagram definitions in Mermaid, PlantUML, or GraphViz syntax; Kroki handles the rendering. Simple, decoupled, reliable.
The Payoff

Agents that show, not just tell

One call: the agent names a diagram type and describes what to show. The tool emits a Mermaid definition and Kroki returns an SVG — a login flow becomes a picture.

# Agent describes what to show { "name": "generate_diagram", "parameters": { "diagram_type": "sequence", "description": "User login flow with JWT authentication", "format": "svg" } } # Tool generates a Mermaid definition sequenceDiagram User->>Frontend: Enter credentials Frontend->>Backend: POST /login Backend->>Database: Verify user Database-->>Backend: User valid Backend->>Backend: Generate JWT Backend-->>Frontend: Return token Frontend-->>User: Login success # Kroki renders it to SVG
Breadth

One HTTP seam, eight diagram languages

Because rendering is delegated, adding a diagram type costs almost nothing. A single DiagramType enum spans all eight variants:

  • ▸ Flowchart — process flows & decision trees  ·  Sequence — interactions over time
  • ▸ Class — object-oriented structures  ·  ERD — database entity relationships
  • ▸ Architecture — C4 model system diagrams  ·  Mindmap — hierarchical concept maps
  • ▸ Gantt — project timelines  ·  State — state machines & transitions
Defined via the DiagramType enum across 8 variants.
Implementation

Three small parts, easy to extend

The prototype splits cleanly, so new types or templates are additive rather than invasive.

Kroki Client
HTTP wrapper handling API calls, response parsing, and format negotiation. 265 lines in kroki_client.py.
Template Loader
YAML-based template management with validation and variable substitution. 168 lines in template_loader.py.
Validation
Syntax checking before rendering, plus type enforcement via models.py on the diagram definition.
Adding a new diagram type or template is just a YAML file. The core diagram engine is 320 lines in diagram.py.
Status & Direction

An honest prototype — and where it could go

This is a single-commit, currently inactive prototype: proof that giving agents a visual channel is cheap. If revived, several bundles could plug it straight in.

  • ✓ designer — wireframes, user flows, and system architecture during design
  • ✓ full-stack-developer — auto-document APIs, schemas, and component interactions
  • ✓ spec-driven-builder — generate architecture diagrams from specs before writing code
Honest caveat: adoption is illustrative — not verified against live bundle configurations. The tool is a prototype, not a shipped dependency.
