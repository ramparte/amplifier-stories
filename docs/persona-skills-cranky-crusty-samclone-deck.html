The Problem

Personality feels like magic you can't engineer

We treat AI skills as tools — run pytest, format a file. Perspective seems different: fuzzy, subjective, unrepeatable. And a persona someone types by hand is just one author's opinion — you can't prove it's faithful to anyone.

“If a persona is only as good as the paragraph a human wrote for it, how do you know it actually captures a way of thinking — instead of a caricature of one?”

— the question these three skills answer three different ways
Persona 1 · Cranky Old Sam (COSam)

A skill can encode how an AI thinks, not just what it does

Cranky Old Sam is a standalone skill repo whose whole job is to hunt unnecessary complexity. Same SKILL.md format as a tool skill — but it carries a judgment framework, not a command.

The philosophy it carries

  • The burden of proof is on the complexity
  • First question: “what can be removed?”
  • Function instead of a class? Value instead of a function? Nothing instead of a value?
  • Premature generality is debt, not investment

How it's built

  • Standalone repo ramparte/cranky-old-sam, one SKILL.md
  • 5 core behaviors, from Complexity Interrogation to YAGNI Audit
  • Auto-activates on “too complex”, “simplify”, “over-engineered”

“The middleware pipeline has six stages. Three are identity transforms in production. Delete them. The handler registry uses a plugin architecture. You have four handlers, known at compile time. Use a map.”

— Cranky Old Sam, example tone from SKILL.md
Persona 2 · Crusty Old Engineer (COE)

The same format scales to a community-maintained advisor

Crusty Old Engineer proves a persona need not be one author's pet project. It lives in the shared bundle beside 20+ skills, PR-reviewed and evolved by the community — a battle-scarred voice that surfaces failure modes optimistic designs miss.

The philosophy it carries

  • Treat novelty as a liability until proven otherwise
  • Skepticism alone is insufficient — always offer a way forward
  • Anchor claims in evidence: postmortems, SRE refs, canonical papers
  • Asking an agent is not the same as doing the work

How it's built

  • Lives in microsoft/amplifier-bundle-skills
  • One of 21 community-maintained skills in a shared repo
  • 4 core behaviors: Grounded Skepticism, Constructive Progress, Evidence-Linked Judgment, Prior Effort Expectation

The Payoff

Personality is structured data, not magic

Hand-authoring is one path. SamClone proves the deeper claim: voice, values, and judgment are patterns you can extract from interaction data, structure into files, and refresh on a schedule.

Complementary Design

These voices compose — a design can pass one and fail another

The point isn't picking the “right” persona. Cranky Old Sam and Crusty Old Engineer are built to disagree: run both and you get two independent lenses on the same code.

COSam asks

“Why does this exist at all?”

  • What breaks if you remove it?
  • A problem you have, or one you might have?
  • How much must a newcomer understand to change it?

COE asks

“Have you thought about the consequences?”

  • What are the hidden costs?
  • What are the known failure modes for this class?
  • How long will the “temporary” version really live?

“A design can pass COE review and still fail COSam review — it's three times more complex than the problem requires. Use both when the stakes justify it.”

— Cranky Old Sam SKILL.md, “Relationship to COE”

Lessons

What personas teach us

Skills encode perspective

A SKILL.md that says “question every abstraction” changes AI behavior as reliably as one that says “run pytest.” The format was built for tools; it works for judgment.

Personality is structured data

SamClone shows voice, values, and judgment can be computationally extracted, filed, and refreshed on a schedule — patterns in interaction data, not magic.

Depth matches the problem

A simplicity review needs one file. A full persona clone needs 10 files and 3 agents. Same format, scaled to the perspective — and they compose into real workflows.
