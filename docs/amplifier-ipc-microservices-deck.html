The Problem

The architecture that reached v1 is the ceiling on v2

🔗

Dependency Hell

Every tool, hook, and provider shares a single process. One package conflict breaks everything. Anthropic SDK pins clash with OpenAI pins.

🔒

Python-Only Lock-In

Dynamic import_and_create() machinery ties every component to Python. No path to Rust tools, Go providers, or TypeScript hooks.

💥

Blast Radius

A crashing tool takes down the entire agent session. No process isolation means no fault boundaries.

Every component shares memory, shares dependencies, shares fate. The in-process design that got Amplifier to v1 becomes the wall that prevents v2.

The Solution

Every component runs as its own container-in-waiting

Each tool, hook, and provider runs as its own subprocess. A central Host routes messages over JSON-RPC 2.0 via stdio — so the IPC boundary you get today is the network boundary you deploy tomorrow.

What you get today

  • Process isolation — a crash can't spread
  • Dependency freedom — each service its own uv virtualenv
  • Language-agnostic wire format — JSON-RPC, not Python imports
  • Fresh processes per turn — no stale state, no concurrency bugs

What it unlocks tomorrow

  • The subprocess boundary becomes a container boundary
  • Business logic doesn't change — only the transport
  • Any HTTP server can implement a component
  • A clean path from monolith to service mesh
Mechanism · Per-Turn Lifecycle

Fresh processes every turn keep isolation cheap

1

Spawn

Host spawns all service subprocesses from isolated uv virtualenvs. Each service gets its own dependency tree. ~200ms startup cost, paid once per turn.

2

Discover

Host sends describe to every service — builds a routing table of tools, hooks, providers, and content manifests. No static config needed.

3

Route

Orchestrator drives the agent loop. All tool calls, provider requests, and hook events flow through the Host as a dumb message bus. Fan-out, chaining, parallel dispatch.

4

Tear Down

Turn completes. SIGTERM all services, SIGKILL after timeout. Next turn starts fresh — clean processes, clean state, zero stale memory.

Mechanism · Separation of Concerns

The Host stays dumb so the orchestrator can own the logic

🎯

CLI / REPL

User-facing entry point — Click + Rich + prompt-toolkit

📡

Host

Dumb message bus — spawns services, routes requests, persists transcripts

🧠

Orchestrator

Agent loop driver — calls providers, tools, hooks via JSON-RPC

The Host does NOT interpret hook results, drive the agent loop, hold conversation state, or call LLMs. It's a router. The orchestrator owns all logic — which is exactly why the transport can be swapped later.

What runs on it

13 services in one mono-repo, discovered by decorator

A service is just a Python package that exposes components via decorators — the Host discovers them automatically, no YAML registration of individual tools.

Behavior services

amplifier-foundation (orchestrator, context, core tools/hooks), amplifier-modes, amplifier-skills, amplifier-routing-matrix.

Provider services

amplifier-providers — 8 LLM adapters with streaming, plus specialist services like filesystem and browser-tester.

Content-only services

amplifier-recipes, amplifier-core and more — pure context and definitions, zero custom code.

The Dapr Future

Today's subprocess boundary is tomorrow's container boundary

Swap the stdio IPC layer for Dapr-native microservices and every behavior becomes its own container — ~28 of them, decomposed from today's 13 services.

Why Dapr

  • Service invocation with mTLS, retries, circuit breakers
  • Pub/sub for streaming tokens and hook fan-out
  • State store for session persistence (Redis)
  • Built-in observability and tracing

The Decomposition

  • ~28 application containers from today's 13 services
  • Foundation alone splits into 14 behavior containers
  • Shared base image + thin SDK keeps overhead minimal
  • Standard HTTP endpoints — no custom protocol
# Three communication patterns cover all interactions: Pattern 1: Request/Response # tools, providers, /describe Pattern 2: Pub/Sub Streaming # LLM tokens -> orchestrator -> CLI Pattern 3: Pub/Sub Hooks # lifecycle events, parallel fan-out

Process Isolation

📦

Dependency Freedom
