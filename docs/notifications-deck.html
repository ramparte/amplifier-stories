The Complication

Long operations break flow

The agent works async — but your attention doesn't, so you keep glancing back at a spinner.

Tab Switching
You start a recipe, switch to Slack, forget to check back. Five minutes wasted.
Terminal Watching
Staring at a spinner is not productive work. Your attention is worth more.
Remote Work
SSH'd into a server, walk away for coffee, come back 20 minutes later wondering if it finished.
The naive fix — alert on everything — is worse: a ping for every sub-agent and recipe step trains you to ignore all of them.
The Payoff

It notifies only when you are the blocker

Sub-agents and intermediate steps stay silent. You hear from Amplifier exactly when a human decision is needed — and never otherwise.

Interactive session completes✓ Notifies — you're waiting
Sub-agent finishes✗ Silent — parent handles it
Recipe step completes✗ Silent — not final
Recipe finishes entirely✓ Notifies — input needed
Terminal is focused○ Optional — suppress_if_focused
Focus detection uses tmux pane state, the macOS frontmost app (osascript), or Linux xdotool to decide whether a ping is even warranted. Everything that follows is how this reaches you.
What It Is

One bundle: desktop by default, phone when you want it

The notify bundle ships two hook modules that listen for the moment a turn completes and a human is needed.

hooks-notify (Desktop)
Native OS notifications or terminal escape sequences. Zero external dependencies on macOS. Auto-detects SSH and terminal emulator. Included by default.
# auto, terminal, or desktop method: auto suppress_if_focused: true show_preview: true
hooks-notify-push (Mobile)
Push to your phone via ntfy.sh — open-source, no signup. Listens to the notify:turn-complete event emitted by hooks-notify. Opt-in.
# topic from AMPLIFIER_NTFY_TOPIC env service: ntfy priority: default tags: [robot]

Message format everywhere: device | project | content.

Privacy-First

Designed so you can actually leave it on

⚠️ ntfy.sh topics are PUBLIC
Anyone who knows your topic name can read your notifications or send messages to it.

The push module loads topics from AMPLIFIER_NTFY_TOPIC only (typically ~/.amplifier/keys.env). Topic values in config files are explicitly ignored by the code.
Env-Only Secrets
Topic loaded from an environment variable, never from settings.yaml. Code enforces the separation.
Self-Host Option
Set AMPLIFIER_NTFY_SERVER to point at your own ntfy instance for maximum privacy.
Easy Disable
AMPLIFIER_NOTIFY=false turns off desktop notifications; the config enabled flag takes precedence.
