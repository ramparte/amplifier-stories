Why It Needed Fixing

The old config was one size fits nobody

🔒
Rigid Provider Config
One instance per provider. Want fast Sonnet and deep Opus from the same provider? Tough luck.
👥
No Team Sharing
Routing config lived in one place. Teams couldn’t share routing via git while keeping API keys personal.
⚙️
Matrix Rigidity
Built-in routing matrices only. No cloning, no customization, no per-candidate config like reasoning effort.
The Payoff

Configure everything, share what matters, keep credentials personal

One idea unlocks the rest: settings now live at three scopes, so the right config sits in the right place.

Global

Personal defaults and API keys. Follows you everywhere. Never committed to git.

Project

Team routing config lives in the repo. Share preferred matrices and provider setups via git.

Local

Per-checkout overrides. Experiment without affecting anyone. Gitignored by default.

# Interactive scope picker on every dashboard [w] Change scope Global | Project | Local
Mechanism — Providers

Run many instances of one provider, each with its own job

The same provider module, configured twice, becomes two first-class routing targets.

Before

  • One Anthropic provider
  • One config set
  • Pick a model, live with it

Now

  • anthropic-fast → Sonnet, low latency
  • anthropic-reasoning → Opus, deep thinking
  • First-class kernel support for every instance
Mechanism — Matrices

Clone any matrix, customize every role, save your own

You never build routing from scratch — and what you build is shareable via project scope.

📋
Clone
Start from any built-in matrix — balanced, quality, fast, local. Don’t reinvent it.
✏️
Edit
Assign provider + model + per-candidate config to each role: reasoning_effort, enable_1m_context, and more.
💾
Save
Save as a named custom matrix. Share it with your team through project scope.

Provider, model, and config travel as a single unit

Trust

Sharing is safe because secrets can’t leak downward

Team sharing only works if committing routing can never commit a key. This is what guarantees it.

26-Key Blocklist

Protected config keys can never be overridden at lower scopes. API keys, tokens, and secrets stay in global scope.

Path Traversal Guard

Config file paths are validated against traversal attacks. No reading outside sanctioned directories.

Deterministic Precedence

Local overrides project, project overrides global — and a deep merge preserves every provider instance, so multi-instance configs never get lost. The blocklist always wins.
