The Reliability Problem

LLMs are brilliant — and you can't trust them to copy a paragraph

The same model that can rewrite a whole document will quietly paraphrase the one section you told it to leave untouched. That nondeterminism is the price of their power — and it's fatal when a task demands exact fidelity. This is the story of a recipe that needed every preserved section kept byte-for-byte, and how wrapping the LLM in deterministic code turned “usually right” into a guarantee.

A problem every LLM has. A fix that doesn't rely on trust.

The Ask

Regenerate the doc — but keep what already works

While regenerating the output of the document-generation-parallel.yaml recipe, the user wanted existing sections kept intact — only outdated parts rewritten.

The Ask

"When I provide an existing document, preserve sections that don't need changes. Only regenerate what's actually outdated."

The Stakes

11 hand-written sections with code examples, commands, and formatting. Lose any of it and it's manual recovery.

"The existing doc is the reference for what is already mainly working."
v7.1.0 — First Attempt

Asking the LLM to "preserve" mangled it

# The prompt approach If action_needed is "none": USE EXISTING CONTENT AS-IS If action_needed is "add": Keep existing, ADD missing content If action_needed is "update": Revise specific parts only

Result: content mangled

The LLM "preserved" content by summarizing it. Code blocks were paraphrased. Commands were reformatted. Nothing came back verbatim.

Lesson: asking an LLM to "copy exactly" doesn't mean it will.

Root Cause

LLMs can't be trusted to copy — or to skip

🤯

The "skip these sections" problem

Even told "these sections are preserved — don't modify them during validation fixes," the model would agree…

The LLM: "Sure!" *proceeds to rewrite them anyway*

💡

The instruction was never the fix

LLMs cannot reliably follow "copy exactly" or "skip these sections." They will still touch, reformat, or "improve" content they were told to leave alone. No prompt makes that a guarantee.

The Pattern

Let the LLM work — then restore with code

Stop hoping the model skips things. Let it do its pass, then deterministically put the preserved sections back. That's what turns "usually right" into 100% fidelity.

v7.5.0 — The Parser Bug

Even the code had a determinism bug

🐛

Code comments mistaken for headings

The section extractor wasn't tracking whether it was inside a code fence. Every # comment inside a fenced block looked like a new heading — so sections got truncated. Section 1.2.1 came back as 99 characters instead of 737.

def parse_markdown_sections(content): in_code_block = False # Track state! for line in content.split('\n'): if line.startswith('```'): in_code_block = not in_code_block continue if line.startswith('#') and not in_code_block: sections.append(parse_heading(line))

Key Insight
💡

When Determinism Matters,
Use Code Not LLMs

LLMs are powerful for generation and analysis. But for exact reproduction, byte-level accuracy, or strict constraints, a 10-line Python function beats a 100-word prompt. Wrap the model; restore with code.
