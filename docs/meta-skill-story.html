Act 1 · Feb 13

It began as pointers, not knowledge

“I want to create a new skill that stands up a new service… Make sure ALL the changes needed are captured.”
— The user, after building 3 services by hand

The insight was to build real things first, then extract the pattern. V1 shipped deliberately minimal: a single SKILL.md, 365 lines, referencing live files in gh-issues-local/.

The Hidden Fragility

The skill didn’t contain the knowledge — it contained pointers to it. Every section said “See gh-issues-local/src/app.py for reference.” Those pointers assumed gh-issues-local would exist forever, unchanged, in the same place.

Act 2 · Feb 17 – Mar 3

Pointers rot: ~30 references broke when the workspace moved

Feb 17
✓ First real test: nl-spec-generator
Four days after creation the skill got its first use — a new service scaffolded by following the SKILL.md instructions. Validation passed.
Feb–Mar
The workspace churned
github-local was retired, Gitea replaced it, services were refactored, moved, and renamed. The codebase the skill pointed at was a moving target.
Mar 3
✗ ~30 references break
During the Gitea migration the AI found ~30 stale references in SKILL.md, all pointing to the retired gh-issues-local. Every “see gh-issues-local/…” was now a dead link.
Act 3 · Mar 4 · The Payoff

The fix: templates the skill carries itself

“Come up with a plan to store sample files in that directory, so we are not reliant on any service.”
— The user, articulating the core insight

26 templates, zero dependencies

The AI proposed 26 template files with placeholder tokens — extracted from issues-to-brief and even recovered from the retired github-local’s git cache. Dead code became reusable templates.

Worked on the first try

Hours after the V2 conversion, the skill built The Garden’s web frontend — loading templates from templates/web/ as its foundation. Nothing external to break; it just worked.

Mechanism — Tokens

Placeholder tokens are the abstraction layer

# pyproject.toml template [project] name = "{{PACKAGE_NAME}}" version = "0.1.0" [project.scripts] start = "{{PACKAGE_NAME}}.app:main" # vite.config.ts template export default defineConfig({ server: { port: {{PORT_BASE_PLUS_1}}, proxy: { '/api': 'http://localhost:{{PORT_BASE}}' } } })

{{SERVICE_NAME}}

Directory name, display strings

{{PACKAGE_NAME}}

Python package, imports

{{PORT_BASE}}

Backend port, frontend proxy

Mechanism — The Spec

Under the hood it’s just the Agent Skills spec

Nothing here is bespoke. Skills follow the Agent Skills specification: a SKILL.md with frontmatter, plus optional companion files the agent loads on demand. Templates are just assets.

Standard Skill Structure my-skill/ SKILL.md # Required: frontmatter + instructions references/ # Optional: additional docs assets/ # Optional: templates, data files scripts/ # Optional: executable code --- SKILL.md frontmatter --- name: my-skill description: Apply X when Y happens ---
scaffold-new-service (V2) scaffold-new-service/ SKILL.md # 255 lines, 11 steps templates/ # 26 files (= assets) pyproject.toml # {{PACKAGE_NAME}} src/app.py # FastAPI factory src/auth.py # Bearer middleware web/ # React + Vite frontend ... # load via read_file(skill_directory # + "/templates/foo")
The Repeatable Process

The real artifact is the process, in six moves

01
Build First, Extract Later
Don’t design skills in the abstract. Build something real by hand, then ask “what’s the reusable pattern?” This skill was extracted from 3 real services.
02
AI as Pattern Miner
Ask the AI to explore existing implementations and propose what a generalized skill should contain — artifact inventories and clarifying questions included.
03
Human Directs, AI Executes
The AI proposes options; the human makes the architectural calls. “Templates vs. instructions” and “auth is optional” were human decisions.
04
Start Minimal, Harden on Pain
V1 was minimal on purpose. Only when references broke did templates earn their cost — motivated by a real failure, not premature polish.
05
Self-Contained > Cross-References
Bundle template files with {{PLACEHOLDER}} tokens so the skill doesn’t depend on any service existing. Carried templates don’t rot.
06
Validate Immediately
Use the skill on a real task at once. V1 was validated 4 days later on nl-spec-generator; V2 the same evening on The Garden.
The Punchline

The process is itself a skill

Build, extract, mine, decide, start minimal, harden, validate — a repeatable, teachable pattern. Which is exactly what a skill is.

Try the Process

1. Build something real by hand, at least twice

2. Ask the AI to mine the pattern

3. Make the design decisions yourself

4. Start with instructions; upgrade to templates when the pain demands it

5. Validate immediately on a new project
