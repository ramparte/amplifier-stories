The Complication
One model's answer is just one opinion.
And a confident model can be confidently wrong.
Code review catches bugs. Pair programming catches design flaws. But every architectural decision you ran past an AI came back with a single verdict from a single model—no second opinion, no way to tell a sure answer from a lucky one. What if you could run that same decision past four different models at once, and only proceed when they converge?
The Payoff
Convergence is confidence. Divergence is a signal.
Run one question through independent models. When they agree, you know you're right. When one dissents, you know exactly where to dig.

When they agree

3 of 4 converge on the same approach → high confidence. Ship it.

When one dissents

The outlier isn't wrong—it may have caught an edge case the others missed. Examine it before you move.

This convergence test is the whole idea. Everything that follows is how it became possible—and who proved it.
The Pioneer
Samuel Lee proved it as a personal experiment.
“What if I ran the same prompt through Anthropic, OpenAI, Gemini, and GitHub Copilot at the same time? If three out of four models agree on the architecture, I know I'm on the right track.”
— Samuel Lee, MADE:Explorations
Samuel Lee—a senior engineer on the MADE team—pioneered running four providers simultaneously for cross-validation. What started as a personal workflow is now becoming standard practice across the team. The rest of this story is why the architecture let him try it in an afternoon.
Why It Was Inevitable
Nobody planned cross-validation—the architecture did.
Amplifier's kernel provides mechanism; modules provide policy. Each provider is just a module you compose into your bundle. Because adding a provider is trivial, running four at once was always latent in the design—waiting for someone to ask “what if?”

Composition, Not Configuration
A four-provider swarm is a few lines of YAML.
Adding a provider is a three-line change. Running four simultaneously is just four includes—then you route agents to whichever models you want cross-checking each other.
# Bundle YAML — compose your provider swarm providers: - module: provider-anthropic config: default_model: claude-opus-4-6 enable_1m_context: true - module: provider-openai config: default_model: gpt-5 - module: provider-gemini config: default_model: gemini-3-pro-preview - module: provider-github-copilot config: default_model: claude-sonnet-4
The Compounding Effect
The same composability makes the swarm grow and deepen on its own.
Because providers are modules, the swarm isn't fixed—each provider gets wider and each new one drops in without touching the others.

Copilot joined in a day

Marc Goodner built the GitHub Copilot provider in a single day—8 commits, 10 modules, an 80% coverage threshold. Zero API keys: it authenticates through your existing Copilot subscription and unlocks every model in your plan.

Anthropic reached 1M tokens

Samuel Lee's beta-headers commit enabled million-token context; Brian Krabach extended it to Opus with model-family-aware defaults (128K output, 64K thinking) and adaptive thinking—the model decides when to reason.

Not A Demo
Swarms are already daily practice on the MADE team.
These aren't experiments—they're workflows running right now, routed through whatever provider swarm each bundle configures.
  • Docs freshness validation
    Multiple models cross-check documentation pipelines, catching staleness a single model misses.
  • NL spec creation
    When Claude, GPT, and Gemini all parse a natural-language spec the same way, it's unambiguous.
  • Slack-driven sessions
    Messages flow through the configured swarm, so debugging suggestions are already cross-validated.
