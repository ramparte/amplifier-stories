The Complication

Every code search
is half-blind

🔍

grep Doesn't Understand

Keyword search finds text, not meaning. “How does authentication work?” returns nothing useful — the code says r.URL.Query(), not “authentication.”

🧠

Embeddings Miss Symbols

Pure vector search captures intent but fumbles exact lookups. “Find semverParse” should be a precise hit, not a fuzzy semantic match.

📈

Nothing Scales

Enterprise codebases have 100K+ files. IDE search is local, GitHub search is rate-limited. No tool combines understanding with scale.

Developers spend 58% of their time understanding code, not writing it. Retrieval is the bottleneck — and no single index can solve it.

The Payoff

Three indexes,
one query

OCTO fuses dense vector embeddings, BM25 keyword search, and LLM-generated summaries into a single retrieval pipeline. One query answers symbol lookups, architectural questions, and concept searches alike — each index covering the blind spot of the others.

From “Where is semverParse defined?” to “How does JWT signing work?” — one system, one query, the right files. The rest of this deck is how that fusion is built and proven.

The Pipeline

One query fans out, then fuses back together

1

Classify

A deterministic query router uses a 5-pass heuristic to detect symbol names, keyword prefixes, CamelCase identifiers, and comprehension queries — no LLM needed at query time.

2

Search in Parallel

Three plugins fire simultaneously: QdrantCode (chunk embeddings), QdrantSummary (LLM file summaries), and ConceptCluster (topic groupings). Results fuse via Reciprocal Rank Fusion.

3

Post-Process

Dedup, score normalization, optional cross-encoder reranking (ms-marco-MiniLM), and top-K filtering. The best results surface regardless of which index found them.

The Architecture

A plugin orchestrator, three complementary indexes

🔍

5-pass symbol extraction — classifies queries into hybrid or semantic search mode

⚡

🎯

PostProcessor

QdrantCode

Dense vector search over code chunks. 768-dim embeddings via nomic-embed-text, plus text indexes for symbol-level BM25 filtering.

QdrantSummary

Searches LLM-generated file descriptions. Bridges code tokens and conceptual queries like “How does URL handling work?”

ConceptCluster

Topic-level groupings for cross-file concept retrieval. Surfaces related files that chunk search alone would miss.

The Key Innovation

Summary embeddings
cracked comprehension

Raw code embeddings capture tokens, not purpose. OCTO has an LLM describe what each file does at index time, then embeds those descriptions — the move that made vague questions answerable.

The Problem

“How does the code handle URL parameters?” lands in a different vector neighborhood than r.URL.Query() in macaron.go. Pure code embeddings can't bridge that gap.

The Fix

At index time, gemma2:2b writes a plain-English summary of each file. At query time, comprehension queries match summaries and the correct files surface.

Measured impact: +5 comprehension hits (+12 percentage points) from summary search alone. Combined with cross-encoder reranking: +7 hits total, reaching 81% comprehension accuracy.

Why The Numbers Hold Up

The 88% is honest because the tuning was ruthless

Every feature earned its place by measurement — and the ones that didn't were cut.

Cut What Hurt

Query expansion (−4 hits) and chunk enrichment (−3 hits) were measured to hurt retrieval — so they were disabled. Only proven improvements shipped.

Full-Set Honesty

The primary metric includes questions whose expected files weren't even indexed — no cherry-picking the winnable ones.

Ranked, Not Just Found

MRR 0.782 on function lookups means the correct file is usually the #1 result — not merely somewhere in the list.

Enterprise Scale

Built to hold up on real, huge codebases

Scale

  • Tested on Grafana: 11K files, ~110K chunks
  • Feasible: 100K files on a single machine
  • Qdrant handles 10M+ vectors natively (HNSW)
  • Cross-encoder is always O(top-50), regardless of index size
  • 16 file types: Python, TypeScript, Go, Rust, Java, Kotlin, Swift, Ruby, Shell, and more
  • Resume-safe indexing: --append resumes runs, --file-list re-indexes targeted files

Stack

  • Python 3.10+ — 6 CLI scripts, ~3,200 lines
  • Qdrant vector DB with text indexes; Ollama nomic-embed-text (768-dim)
  • Plugin orchestration — ~3,700 lines
  • Concept clustering — topic analysis (~8,400 lines)
  • Taste Library — team-convention reranking (~1,600 lines)
  • Query classification is fully deterministic — no LLM at query time

Quick Start

Index, search, evaluate — try it

# Check prerequisites (Python, Qdrant, Ollama) python3 scripts/check-env.py # Index a codebase into Qdrant python3 scripts/index-repo.py /path/to/repo \ --collection my-repo --workers 6 # Search with natural language python3 scripts/search.py \ --query "Where is the authentication handler?" # Run retrieval evaluation against a golden set python3 scripts/run-eval.py \ --golden-set golden.json \ --enable-summaries --enable-cross-encoder # Launch the web dashboard python3 scripts/server.py --port 8080
