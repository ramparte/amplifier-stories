Mechanism · Detect

It only touches what actually changed.

Every documented section is fingerprinted with a content hash. Each day the pipeline re-hashes the source and diffs against the baseline — so only genuinely drifted sections trigger downstream work. No wasted compute, no needless rewrites.

# daily hash diff providers/anthropic.md hash changed → regenerate cli/commands.md hash match → skip recipes/overview.md hash match → skip config/schema.md hash match → skip
83
sections fingerprinted by hash

Content hashing is the gate: it keeps a 34-repo sweep cheap enough to run every single day without burning compute on docs that are already correct.

Mechanism · Verify

Nothing commits until it's checked against source.

After a section is regenerated, a second AI pass checks every factual claim it makes against the actual source code. Not just AI-generated — AI-verified.

✏️
Regenerate
AI surgically rewrites only the drifted section. Everything already accurate stays untouched.
›
🔬
Verify
A second pass checks every claim against source. Wrong model name? Fix it. Stale config key? Remove it.
›
✅
Commit
Only evidence-grounded changes commit — atomically, with updated hashes.

Factual corrections even bypass the cosmetic-diff filter: a one-character model-name fix ships regardless of how small it looks. Accuracy always wins over brevity.
