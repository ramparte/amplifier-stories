Why You Need It

shadow-operator can't grade
its own homework.

shadow-operator snapshots your local repos, builds the container, and rewrites git URLs to point at those snapshots. But if the person who built the environment also declares it correct, a silent failure never surfaces.

🔀
Silent rewrite failure
If git URL rewriting doesn't take, fetches fall back to upstream — and you're testing the wrong code without knowing it.
🏗️
Multi-repo blast radius
Changes span amplifier-core, amplifier-foundation, and modules. Each snapshot must be verified independently.
🐳
Isolation you can't see
The container looks fine from the outside. Whether it's really isolated from your host needs direct evidence.
The Payoff

Trust comes from independence
+ refusing to fake it.

Because the agent runs separately from shadow-operator and halts instead of working around a broken shadow, a PASS actually means your changes ran — not that a check was skipped.

PASS means your changes work. FAIL means stop and investigate. The one thing it will never do is report green when it couldn't actually run your tests.

How A Pass Is Earned

Five weighted categories — and criticals can veto the score.

The rubric totals 100 points across five categories; score ≥ 75 to pass.

Category Points Checks What It Validates
Source Verification 25 4 Snapshot commits exist, git URL rewriting configured, installed package uses snapshot
Installation Health 20 3 Package installs clean, imports work, CLI responds
Code Execution 30 3 Changed modules load, basic functionality works, integration test passes
Isolation Integrity 15 3 Container hostname differs, host home not accessible, env vars correct
No Regressions 10 2 Standard imports work, basic operations complete

Critical failures override the score. If Source Verification, Code Execution, or Installation Health scores zero, the verdict is FAIL regardless of total points.

The Design Decision That Keeps It Honest

It halts instead of working around a broken shadow.

The agent's core principle: if it can't do its job, it stops immediately and says why — rather than quietly downgrading to a test that would pass.

🛑
Mandatory halt conditions
No shadow_id, shadow not found, container not running, or shadow tool unavailable — any of these is an immediate halt with a structured error.
🚫
What it must never do
Never test on the host as a "workaround." Never skip shadow-dependent checks. Never give PASS if it couldn't actually run the tests.
📋
Evidence for every check
The verdict carries per-category scores plus specific pass/fail evidence for each of the 15 checks — nothing is asserted without proof.
Verifying YOUR Change

It runs repo-specific checks to prove your code actually loads.

Generic container health isn't enough — the agent tailors its execution tests to whichever Amplifier repo you changed.
