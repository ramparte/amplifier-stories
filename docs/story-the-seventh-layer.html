This is a story about a 7-stage AI research pipeline — and why the fix was never one more instruction. Here is how it was earned.
7-Stage Pipeline Agent Architecture Cognitive Routing
02 — The Contract
Downstream specialists depended on a strict schema.
In the pipeline, the Researcher gathers evidence and hands it to later specialists. They can only parse one exact shape. No schema, no chain.
✓  Expected schema
// confidence confidence: "high" ← ≥ 0.8 confidence: "medium" ← 0.5–0.79 confidence: "low" ← < 0.5 // tier tier: "primary" tier: "secondary" tier: "tertiary"
The Researcher's job
The Researcher produces beautiful, detailed research: 10–20 web searches, credibility assessment, synthesized findings, narrative prose. Its one required exit condition is to emit that schema exactly. That is the contract the next slide breaks.
03 — What Actually Arrived
Every run produced narrative — not the schema.
Not close. Not almost. Across 4 test runs and 3 topics, zero compliant outputs. The content was excellent; the shape was always wrong.

Enforce harder failed every time.
Everyone who builds agents has this instinct. The format failed — so add more format instructions. Six layers deep, the format still failed. Every time.

05 — The Reframe
The model wasn't disobedient. It was in the wrong cognitive mode.
Research and formatting are different tasks — and the mode always wins.

By synthesis time, the format spec is buried under thousands of tokens of evidence, and the model is deep in narrative mode. A seventh enforcement layer was never going to change that. The prompt isn't the problem — the pipeline design is.
06 — The Fix
Strip all 150 lines. Add one stage.
Accept that the Researcher produces narrative — stop treating that as a failure. Promote a Formatter to a mandatory stage: no bypass, no exceptions. That is the seventh stage, not a seventh enforcement layer.

One claim: don't ask one stage to research and format. Route each cognitive mode to the stage built for it.
The Formatter never researches. It receives content in any form and applies deterministic rules — the narrow, mechanical task that format enforcement always was.
07 — What the Formatter Does
Any input in, canonical schema out — deterministically.
// Confidence: numeric → categorical 0.97 → "high" ← ≥ 0.8 0.62 → "medium" ← 0.5–0.79 0.34 → "low" ← < 0.5 // Tier: shorthand → full word "T1" → "primary" "T2" → "secondary" "T3" → "tertiary" // Sources: partial → validated URL name only → "unknown" partial → full https:// or bust
One claim: each specialist now does exactly one thing, in the cognitive mode that thing actually requires. Formatting became a lookup, not a plea.

When a prompt-level instruction fails consistently — not occasionally, not in edge cases, but every single time — that pattern is a diagnostic signal: stop enforcing, start routing. Give each cognitive mode its own stage.
Sources & Methodology

Type: First-person engineering account of an agent-pipeline architecture change.

Reported metrics (author-observed, direct observation):

  • Format enforcement: 150 of 393 prompt lines — more than one third of the Researcher prompt
  • Six distinct enforcement layers in a single prompt (contract block, Stage 0 pre-commit, rigid template, compliance note, final self-check, annotated examples)
  • Failure baseline: 4 test runs across 3 topics — 0 compliant outputs
  • Validation run: "What is Jina AI?" via Researcher → Formatter → Writer
  • Result: 43 claims extracted, all categorical/full-word/valid-URL; Writer brief with 10 citations; ran end-to-end without intervention

Caveats: Metrics are author-reported from a single development session, not an independently reproduced benchmark. The "one run" validation demonstrates the architecture change but is not a statistical sample.

Takeaway framing: Consistent, non-stochastic prompt-level failure is treated here as a routing signal — evidence the task belongs in a different pipeline stage, not that the prompt needs more enforcement.
