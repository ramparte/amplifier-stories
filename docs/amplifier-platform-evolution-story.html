The most ambitious idea fought the tooling at every turn

The Goal

Pin module dependencies to specific commits for stability—via a pinned_sources.yaml, git clone at session startup, and hash-based URL references.

Where It Broke

  • Git clone can't checkout arbitrary commits directly
  • URL format traps: #hash creates tarballs, @hash is treated as a branch
  • Permission issues, cache corruption, Docker build problems

Sometimes simpler wins—and reverting is judgment, not failure

  • Reverted to pre-installed modules in pyproject.toml pointing to @main
  • Versions locked at Docker build time, not runtime
  • No runtime git complexity; faster session startup
  • Simple dependency management that works with the tooling

Key Insight: "Sometimes the simpler solution is better than fighting tooling limitations." Reverting is engineering judgment, not failure.

Test coverage jumped 6x across every layer

  • Unit (68): config validation, encryption, models
  • Integration (99): database operations, API endpoints
  • E2E (113): full request/response cycles
  • 110+ new tests across 4 files; 15+ obsolete tests removed

Result: 67 → 400+ tests through systematic, layer-by-layer expansion

Cleanup shrank the API from 40 to 37 endpoints

  • Removed 3 helper endpoints (POST /configs/{id}/tools, /providers, /bundles)
  • Configs now modified via a direct PUT /configs/{id}—pure CRUD
  • Added a global registry API for tools/providers/bundles
  • JSON config storage with encryption (replaced YAML strings)

Result: 40 → 37 endpoints and a clearer, more predictable API surface

Lost work came back from patches and diffs

  • JSON storage work was accidentally lost during the git revert of the pinning attempt
  • Recovered from patch files and git diffs
  • Migrated config storage: YAML strings → JSON dicts (config_json JSONB column)
  • Added encryption support via ConfigEncryption

Result: Structured, encrypted config storage—rescued, not rewritten from scratch

The net: production-scalable, tested, pragmatically stable
