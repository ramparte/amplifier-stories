The Project

amplifier-app-benchmarks was built with Amplifier, on Microsoft's eval-recipes

A regression suite for the Amplifier CLI — assembled using Amplifier itself and standing on eval-recipes, Microsoft's battle-tested evaluation framework, which brings Docker isolation and parallel execution for free.

The Challenge

Validating the CLI is complex — the traditional path is weeks

  • Validate capabilities across multiple AI providers
  • Ensure bash, web, PDF, and agent tools all work correctly
  • Catch regressions before users ever hit them
  • Traditional approach: weeks of harness development
The Payoff

Hours, not weeks — because the tool tested the tool

The strongest validation of a dev tool is using it to build its own infrastructure. Amplifier drafted the tasks, wired the configs, and ran the evaluations — turning weeks of harness work into an afternoon, with a suite you launch in one line:

# Execute the full regression suite uv run amplifier-benchmarks run data/run-configs/regression.yaml --max-parallel 15
How It Works · 1 of 2

Docker isolation and parallelism make every result reproducible

Clean-container isolation
Each test runs in a fresh Docker container, so results are reproducible and never leak state between runs — a pass means the same thing every time.
Parallel execution
Configurable concurrency (--max-parallel 15) runs many tests at once, so a full suite finishes fast instead of crawling test-by-test.
How It Works · 2 of 2

Semantic, YAML-driven tests catch failures a string-match would miss

Semantic evaluation
AI-powered checks judge whether a response is actually correct in context — catching nuanced regressions that brittle exact-match assertions sail right past.
Declarative YAML
Tests are readable, reviewable configuration — not code. Adding a new case is editing YAML, which keeps the suite extensible by anyone.
