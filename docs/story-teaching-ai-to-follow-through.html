The Thing Being Fixed

Canvas Specialists chains expert agents into one sourced document.

Canvas Specialists is a bundle of domain-expert AI agents — researcher, writer, data-analyzer, competitive-analysis, storyteller — designed to chain together and produce trustworthy, sourced documents.

What the chain is supposed to do:

Researcher → Writer → Polished Brief

A coordinator LLM decides which specialists to call and hands their output down the line. When it works, the user gets a finished brief — never the machinery behind it. Except it didn’t always work.

What Broke

The coordinator stopped early — and dumped raw machine output.

Roughly 40% of the time the coordinator halted at the researcher and surfaced structured research blocks instead of completing the chain to the writer.

Researcher → RESEARCH OUTPUT {raw block} ×
What users received
RESEARCH OUTPUT Topic: Pomodoro Technique Confidence: 0.82 EVIDENCE_BLOCK_START claim: "25-minute intervals" source_tier: secondary EVIDENCE_BLOCK_END
What users wanted
The Pomodoro Technique A time management method developed by Francesco Cirillo in the late 1980s, using 25-minute focused work intervals separated by short breaks. Sources: [1] [2] [3]

The ~40% failure rate is an observed estimate from repeated use, not a controlled measurement.

The Fix

The fix was instruction design, not code.

Instead of building routing logic, validation layers, or retry mechanisms, the whole change was natural-language rules added to a single instruction file — ruthless simplicity over edge-case coverage.

# File changed: context/specialists-instructions.md # Approach: Natural-language rules for the coordinator LLM Two core behaviors: always chain + an escape hatch No conditional routing code No validation layers No retry logic

One claim: the right place to change the behavior was the instructions the model reads, not the code around it.

Why It Matters

Not because the model got smarter.
Because the instructions got clearer.

~40% reliable → >90% reliable

A better-written instruction file — not a new model, not application logic — moved the chain from ~40% to >90%. That’s the payoff. The rest of the story is how the last stubborn failure mode got closed.

The Loophole

Then the model found a loophole.

User: “Tell me about spaced repetition” Expected: researcher → formatter → writer Actual: Conversational reply. No specialists called. Coordinator reasoning: “Casual phrasing, general-knowledge topic —  deploying a multi-agent pipeline would over-engineer it.”

Rule 1 said “always chain” — but also “when applicable.” The model decided “tell me about” wasn’t applicable. That’s the most common prompt pattern there is, so the reliability number was still at risk.

Closing the Loophole

A routing decision table made casual phrasing chain anyway.

Instead of adding more abstract rules, one concrete table was added after Rule 1. It closes the loophole by making “tell me about X” an explicit example in the “Chain” row.

User’s message is about... Action
A factual topic, person, company, product, technology, or concept Chain. Even casual phrasing (“tell me about X”) gets the pipeline.
A comparison of two or more things Chain via competitive-analysis → writer.
Analysis, insights, or investigation Chain via researcher → analyzer → writer.
The system itself, meta-questions, follow-ups Answer directly.

Table is verbatim from the committed context/specialists-instructions.md (commit 521c1a0).

The Tiebreaker

One sentence resolved everything the table didn’t.

“When in doubt, chain.”

The user can always ask for a shorter answer; they can’t retroactively ask for better sourcing. One tiebreaker rule, added directly below the routing table, gave ambiguous prompts a safe default.

One sentence. Added to specialists-instructions.md beneath the routing table.

Validation
5/5

Re-tested: every scenario passed — and the coordinator cited the table.

✅ “Tell me about spaced repetition”

Now chains through researcher → formatter → writer. The coordinator quoted the routing table: “factual topic... even casual phrasing gets the pipeline.”

✅ Clean handoff narration

Status lines at each handoff with no extra coordinator commentary between them. The narration is the commentary.

The table didn’t just constrain behavior — it gave the model a framework it could reason from and point to.

Re-test after routing table: 5/5 passing (not independently re-verified). Log: docs/test-log/chains/2026-03-05-chain-reliability-smoke-test.md

The Lesson

The right layer to fix AI behavior is sometimes natural language.

📋

Decision tables beat rules

A routing table with concrete examples closed the loophole that abstract rules left open. Models follow examples better than principles.

🎯

One sentence beats ten

“When in doubt, chain” resolved the ambiguity a whole paragraph of caveats had created. Shorter instructions, clearer behavior.

🛠

Good enough beats perfect

A code-level hook would be more reliable than prompt-level narration — but >90% is good enough when the backlog holds higher-leverage work.
