THE GOAL

The goal: an AI that stops learning at 1914

A “timecapsule LLM” trained only on pre-World War I text — language, knowledge, and perspective with no computers, no internet, no modern world.

Standing on shoulders

CRISIS #1
🚨
HTTP 429

The Archive said “stop” — and the official library wouldn't help

Internet Archive's rate limits are undocumented, and its own Python library refuses to manage them for you.

# What happened 12 workers → banned immediately 2 workers → still banned Added delays → STILL banned Made delays longer → STILL BANNED # Found in the docs: "The internetarchive library does not provide assistance with complying with rate limiting."
THE NUCLEAR OPTION

We deleted the official library and built our own rate limiter

robotdad's call: 784 lines gone. Amplifier rebuilt the download layer lower-level, with adaptive backoff tuned to the Archive's real behavior.

Custom adaptive rate limiter

  • Base delay: 3.0 seconds
  • Max delay: 120 seconds
  • On error: delay × 2.5
  • On HTTP 429: delay × 4.0
  • Ban detection: exit after 5 consecutive 429s

The result

Stable downloads. No more bans. The pipeline ran for hours without incident.

Sometimes you need to go lower-level than the official library.

THE BREAKTHROUGH

The Archive has a second, hidden API built for scale

The wall wasn't ours to climb — it was the wrong door. Internet Archive runs two completely separate systems.

Search API

Nice web interface
Great for browsing
Hard pagination limit
We hit the wall at 250

❌ Not for bulk access

Bulk Export API

Direct item access
No pagination theatrics
Reliable metadata fetch
Works every time

✅ Built for scale

# The bulk export endpoint https://archive.org/metadata/{identifier} # Give it an ID, get full metadata back. Every time.
THE SOLUTION

Stop paginating — enumerate identifiers directly

With a bulk endpoint that takes an ID, the job became generating IDs systematically instead of begging search for pages.

1. Discovery

Use the search API just to find initial identifiers and collection patterns

2. Enumeration

Generate identifiers systematically: date-based scanning and sequential patterns

3. Bulk fetch

Pull metadata per identifier via the bulk API — through the custom rate limiter

# Newspaper identifier patterns sim_american-journal-of-science_1800-01-01_1_1 sim_american-journal-of-science_1800-02-01_1_2 sim_american-journal-of-science_1800-03-01_1_3 # Collection + date + volume + issue. Predictable. Enumeratable.
