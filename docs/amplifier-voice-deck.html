The Pattern

Voice is an orchestration layer, not an executor

The voice model never writes code, runs a tool, or does the work itself. It coordinates the specialists that do.

The usual voice assistant
A single model wired to a speech API and a pile of tools. It tries to converse, reason, and execute all at once — inside a tiny real-time context window.
Amplifier Voice
The voice model has one job: decide who to ask. Deep reasoning, code, and research happen in a team of Amplifier agents behind it.
Why it matters: a real-time voice model has a tiny context window. Don't make it think about tools — make it think about which specialist to hand the work to.
1
Pivot 1 · Day 1

Strip every tool but one:
task

Before
// Voice model had direct access to everything tools: [ "flight_tracker", "weather", "calendar", "todo", "task", "web_search", ... ]

Too many tools. Limited context window. Model confused about when to use what.

After
// Voice model has ONE job: orchestrate REALTIME_TOOLS = {"task"} // All real work delegated to specialists // explorer, architect, builder, bug-hunter...

One tool. Clear purpose. Delegates everything to the right specialist agent.

2
Pivot 2 · Day 3

From fire-and-forget
to conversation

task created one-shot agents. delegate enables multi-turn dialogues with persistent state.

Context Control
// Agent gets exactly the right context delegate({ agent: "foundation:explorer", context_depth: "recent", // none | recent | all context_turns: 5 })
Session Resumption
// Resume a prior agent conversation delegate({ agent: "foundation:modular-builder", session_id: "abc-123..." // pick up where we left off })
The unlock: multi-turn agent conversations became possible — the voice model can now carry a task across turns instead of restarting it every time.
3
Pivot 3 · Day 3

The model decides
when to speak

Default voice AI: detect silence → auto-respond.
Amplifier Voice: detect silence → model chooses its moment.

// Semantic VAD + manual response control session.update({ audio: { input: { turn_detection: { type: "semantic_vad", eagerness: "low", create_response: false, // KEY interrupt_response: true } } } }) // After transcription, client triggers: dataChannel.send( JSON.stringify({ type: "response.create" }) )
First attempt: reverted
“True silence mode” was too aggressive. Broke natural conversation flow. Commit fa859f0 → Revert 78441f5
Second attempt: shipped
Separate “detecting end of speech” from “auto-generating response.” The model can now listen to a full multi-sentence request without interrupting after the first pause. Commit a2f6042
Why It Was Possible

Three architectures in four days —
because each pivot was a config change, not a rewrite

3
architecture pivots
1
voice client, unchanged
22
event types streamed live
The lesson: Amplifier's modular architecture meant each pivot was a configuration change, not a rewrite. The voice model didn't change — only its relationship to the agent framework did. And because 22 event types stream live to the browser, none of it was a black box: you can watch Claude thinking, agents spawning, and tools executing in real time. Good infrastructure enables fearless iteration.
