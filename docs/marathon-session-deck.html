Case Study

One Amplifier session shipped an entire TUI — on its own

62 Hours • 9 Prompts • 147 Commits

An Amplifier session built amplifier-tui — a full Textual-based terminal UI for managing sessions, running commands, and browsing history — autonomously, from a single launch.

The Threat

Mid-run, its memory was wiped 631 times

Context isn't free. It grew from 111K toward 1.2M tokens, then compacted — over and over. By the end, nearly all of each cycle's working memory was thrown away. A run that long should have forgotten what it was doing.

The Payoff

631 compactions. Zero lost context.

The session kept building through every wipe — because the orchestrator barely held any state of its own.

103K
Stable Post-Compaction
Working memory settled at ~103–105K tokens after every compaction. A consistent baseline it never outgrew.
Why it survived
The orchestrator only tracked one thing: “what feature am I on?” Everything else lived in disposable sub-sessions and files on disk. Small state survives aggressive compaction — that is the whole trick.
The throughline: long-running agents don't need a bigger memory. They need a tiny orchestrator that delegates the work and keeps its real memory somewhere a wipe can't reach.
The Launch

Prep the memory, then walk away

The developer set the stage first — testing tools, a feature roadmap, a handoff file — then handed off with four lines.

The Prep Work
SVG-based visual verification tools built first. A feature list. A SESSION-HANDOFF.md capturing architecture decisions and conventions.
The Handoff
Point the agent at its own memory file, give it scope and permission, and remove the expectation of a feedback loop.
“Work through as many features as you can, one at a time with subagents so you don’t get exhausted. Commit and push after each one. Be ambitious. I have to leave for a while now.”
— The human’s 3rd prompt, starting the autonomous run. “One at a time with subagents” is the line that defined the whole architecture.
Mechanism — Delegation

The main session never wrote a line of code

It only decided what to build next, then spun up a fresh worker to build it — and threw that worker away after the commit.

Mechanism — External Memory

Files on disk were the agent’s real long-term memory

When context compacts, files survive. SESSION-HANDOFF.md was the lifeline the agent re-read to remember who it was.

Mechanism — Verification

Build the tests before the marathon, so workers self-check

With no human watching, each sub-agent needed a way to prove its own work. SVG-based visual verification gave it one.

tui_capture.py
Headless screenshot via the Textual Pilot API. Captures the TUI as SVG without a terminal.
svg_parser.py
Extracts text, colors, and positions from the SVG. Structured data, not pixels.
ux_test.sh
One-command validation: run, capture, parse, assert. The whole pipeline in seconds.
One claim: parsing SVG for text and layout is deterministic — no model inference, no flakiness — so every disposable worker could verify itself before committing.
The Honest Gap

The one missing piece: a gate to stop rebuilding the same feature

Disposable workers have no memory of each other. With nothing checking what was already done, later batches re-implemented earlier ones.

The Sequel

Session 2 proved it: the backlog became the missing gate

Two weeks later the developer ran the same pattern — but planned first. A specced feature backlog is the deduplication gate session 1 lacked.

Session 1 — Exploration
“Be ambitious, go.” Open-ended, no specs. ~50–60 unique features over 62 hours and 9 prompts. Pioneered the architecture — but duplication crept in.
Session 2 — Exploitation
16 features specced with acceptance criteria and pre-assigned test IDs. 14 shipped in one evening, on a single prompt, with zero duplication.

The Pattern

Design the work.
Let the agent build it.

Across both runs the same five moves carried a long agent. The human’s job was never to write code — it was to architect how the agent works.

  • 1
    Orchestrator + disposable workersMain session stays tiny and delegates everything, so it survives compaction.
  • 2
    External memory filesSESSION-HANDOFF.md on disk is the agent’s true long-term memory.
  • 3
    Commit after each featureNatural checkpoints, easy rollback, progress always saved.
  • 4
    Build verification firstTesting tools before the marathon let workers self-check without a human.
  • 5
    A deduplication gateA specced backlog stops workers rebuilding what’s already done.
