Why This Had To Change

Skills carried knowledge — but real automation still meant writing a full agent

A skill used to be Markdown injected into context. The moment you needed isolated context, a cheaper model, or an enforced guardrail, you had to graduate to a full agent definition — more code, more surface area, less portable.

What a skill could do

  • Inject expertise and instructions
  • Carry companion reference files
  • Portable Markdown + YAML

What forced you into an agent

  • Running work in its own context window
  • Routing to a cheaper or stronger model
  • Always-on guardrails the model can’t skip
The Payoff

A Markdown file is now a lightweight agent runtime

Ten additive frontmatter fields give a skill agent-grade powers — forked execution, model routing, tool limits, lifecycle hooks — while existing skills keep working unchanged.

--- name: code-review description: "Review changed code..." context: fork # run as a subagent model_role: critique # route the model allowed-tools: Read Grep Glob # limit tools user-invocable: true # becomes /code-review --- # The skill body becomes the # subagent's task prompt.

The 10 new fields, grouped

Execution  context, agent, auto-load, hooks

Model  model_role, model, provider_preferences

Invocation  user-invocable, disable-model-invocation

Safety  allowed-tools

Additive by design — every field is optional, so skills written before the upgrade run exactly as before.

Mechanism — Isolation

context: fork runs a skill as an isolated subagent

One field turns a skill into a forked subagent with its own context window — the main conversation stays clean and only gets the summary back.

User runs /code-review
→
Skill body → subagent task prompt
→
Runs in its own context window
→
Summary returns, main context clean

This is the “context-sink” pattern: heavy reference docs live in the fork’s window, never bloating the parent session.

Mechanism — Guardrails

auto-load + hooks make quality gates the agent can’t bypass

A skill can activate itself at session start and inject lifecycle hooks — enforced constraints, not suggestions.

--- name: safety-gate auto-load: true hooks: Stop: - "Never deploy to production" - "without running the test suite." --- # Fires on every response, # enforcing the rule automatically.

Why it holds

  • auto-load: true emits skill:loaded at session start
  • Hook-bearing skills activate their hooks immediately
  • Stop hooks inject constraints the agent must follow
  • Pair with disable-model-invocation: true to make it invisible but enforced
Mechanism — Model Routing

model_role lets a skill declare what it needs, not which model to use

Skills state intent; a 5-level precedence chain resolves it — the same routing mechanism used by delegate and recipes.

What To Keep

Start with a skill; graduate to an agent only when you hit a wall

The upgrade collapses the gap — and your instructions and companion files carry forward if you do graduate.

Reach for a Skill when…

  • It’s packaged expertise or a repeatable task
  • You want it portable and community-shareable
  • You want a /command or an auto-loading guardrail

Graduate to an Agent when…

  • You need custom tool composition
  • You need multi-turn session resumption
  • You need recursive delegation or deep bundle integration

The convergence path: commands already merged into skills, and skills already run as subagents. Skills keep gaining agent powers — so starting with a skill is starting on the winning side.
