Meet the Bundle

amplifier-bundle-agency wraps Microsoft's Agency CLI as Amplifier tools

Microsoft's internal Agency CLI already speaks to enterprise services through 16+ MCP servers. This bundle mounts those servers into an Amplifier session — so an AI agent can drive them through natural language instead of a human clicking through portals.

Why It Was Needed

Every enterprise service
is a wall the agent can't climb

🔒

Walled gardens

Azure DevOps, IcM, Kusto, Teams, SharePoint, M365 — each behind its own API, auth flow, and mental model. No unified interface.

🔄

Context switching

Investigating an incident means jumping between IcM for the ticket, Kusto for logs, ADO for the build, and Teams for coordination. Every hop loses context.

🤖

AI can't reach

The agent watching the same conversation has no native access to any of these services. Manual copy-paste bridges the gap — slowly and unreliably.

An engineer investigating a production incident touches 5+ tools in separate browser tabs. The AI agent in the room can't touch a single one of them — until now.

The Payoff

One conversation runs the whole incident — the agent moves between services, you stay focused

Four services, four sentences. No tab-switching, no copy-paste, no re-auth:

1

“What incidents are active for my team?”

2

3

4

How It Works · 1 of 3

A tool-mcp bridge spawns Agency's servers only when the agent needs them

The bridge is a stdio MCP dispatcher: it starts an Agency CLI process on demand, maps every server's tools into the session as mcp_<server>_<tool>, then lets them go. No persistent daemon, no standing footprint — reach appears the moment it's asked for.

# agent asks for logs -> bridge spawns the Kusto server on demand mcp_kusto_query(cluster="prod", kql="Traces | where ...") # process exits when the call returns — no standing daemon
How It Works · 2 of 3

Six behavior profiles decide which servers are live in a given session

Each behavior YAML declares the MCP servers it needs, so a session only carries the reach its task demands — keeping 16+ servers composable instead of chaotic.

DevOps

Azure DevOps + Bluebird code search — work items, PRs, pipelines, repos, wikis.

On-Call

IcM incidents, Kusto telemetry, CloudBuild — summaries, similar incidents, mitigation hints.

Communications

Teams, Outlook Mail, Calendar — message, schedule, and search conversations.

Search

eng.ms, Microsoft Learn, ES Chat, WorkIQ — internal knowledge, one behavior.

Security

Azure Security Context + S360 Breeze — posture, compliance, vulnerability context.

Productivity

Planner, SharePoint, Word, M365 search — tasks, docs, enterprise search.

How It Works · 3 of 3

Two specialist agents carry the load — and Entra ID makes auth disappear

devops-agent — ~75 tools

Autonomous across ADO + Bluebird. The user describes the outcome; the agent picks the tools.

oncall-agent — ~151 tools

Autonomous across IcM + Kusto + CloudBuild. Together the two agents total the 226 tools.

Zero-config auth: Entra ID handles every credential automatically. No API keys, no OAuth dance, no secrets files — if you're signed into your Microsoft account, the tools just work.

The Bigger Picture

amplifier-bundle-agency proves the pattern at enterprise scale: Agency's MCP servers supply the protocol, Amplifier's bundle system supplies the scoping, composition, and agent delegation. Together — enterprise services as natural-language APIs.
