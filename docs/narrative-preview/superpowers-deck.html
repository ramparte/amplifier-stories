The Evidence · Amplifier + Superpowers
Every phase ships with write tools denied by default
In Amplifier's Superpowers bundle, six modes each declare an explicit tool policy. During the design and execution phases, write_file and edit_file aren't discouraged — they're blocked at the framework level. This is discipline you can read in a config file, not a promise in a prompt.

It's real and it's shipping. The interesting question is why blocking a tool matters at all.
The Complication
The more capable the agent, the better it rationalizes
They skip design, bypass TDD, write code before tests, and claim “it works” without running anything — each shortcut wrapped in a confident, plausible justification. Prompt engineering can only ask them not to. A good enough rationalizer talks its way past every instruction you write.
The five rationalizations, verbatim from real sessions
✘  “Let me just start coding this up” — skips design.
✘  “I’ll add tests after” — bypasses TDD; tests then pass by definition.
✘  “This should work correctly” — claims success without evidence.
✘  “In this case a simpler approach is better” — rationalizes every cut corner.
✘  Long sessions drift — the agent forgets constraints and repeats mistakes.
You cannot out-argue a system that argues back. So don’t argue — remove the option.
The Payoff
You can’t rationalize past a tool that won’t fire.
When write_file is blocked, the agent doesn’t get to argue. There’s no plausible exception, no “just this once.” The tool call comes back blocked — and discipline stops being a request the agent may honor.

Not “please don’t.” Structurally impossible. Here is how the whole workflow makes it so.
How It Works
Each mode swaps the toolset — and denies everything else
A phase isn’t a suggestion about how to behave — it’s a different set of tools. Switch modes and the framework physically changes what the agent can call.
/brainstorm
Socratic design exploration. Facilitates, delegates artifact creation.
write blocked
/write-plan
Create the implementation plan of bite-sized TDD tasks.
write blocked
/execute-plan
Orchestrator dispatches the per-task pipeline. Never writes code directly.
write blocked
/debug
Investigate failures with bash. Delegates fixes to specialists.
write blocked bash safe
/verify
Evidence-based verification. Run tests, confirm edge cases.
write warn bash safe
/finish
MERGE, PR, KEEP, or DISCARD. Requires passing tests to merge.
write warn bash safe
Every mode runs default_action: block — unlisted tools are denied. But policy is only half of it. The other half is who does the writing.
How It Stays Honest
Execution runs on fresh agents that don’t trust each other
The main agent can’t write — so it delegates. Every task from the plan runs a three-agent pipeline, each spawned by the delegate tool into its own clean context window. None of them takes another’s word for anything.
1
Implementer
Failing test first. Minimal code. RED → GREEN → REFACTOR. Atomic commit.
→
2
Spec Reviewer
Reads the spec independently. Nothing missing, nothing extra. APPROVED or FAIL.
→
3
Quality Reviewer
Error handling, security, maintainability. Critical / Important / Suggestion.
Five specialist agents in all, each with one job. “Fresh context” isn’t an instruction here — the delegate tool actually spawns it. Which is exactly what makes this different from the methodology it’s built on.
Why It’s Different
Same discipline. Structural teeth.
Superpowers — Jesse Vincent’s open-source methodology (obra/superpowers, 43k+ stars per its README) — supplies the discipline. Amplifier supplies the enforcement. Every rule that was once a request becomes a property of the framework.

Defense In Depth
Three independent layers — all three must fail at once
Layer 1
Structural
Tool policies block write operations during design phases. The agent physically cannot call write_file. No reasoning bypasses a blocked tool.
Layer 2
Prompt
Anti-rationalization tables pre-empt every known LLM excuse. “This is a simple change” → “Simple changes still need tests.” No wiggle room.
Layer 3
Workflow
Recipes with approval gates require human sign-off before the next phase. The full development cycle has checkpoints you must approve.
Any single layer can fail. All three failing simultaneously? Vanishingly unlikely.
Which turns a hope into a guarantee — and a guarantee is something you can install.
The Takeaway
Stop asking agents to be disciplined.
Make it structural.
