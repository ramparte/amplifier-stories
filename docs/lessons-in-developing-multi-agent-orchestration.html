The Foreman Troubles
What Went Wrong

The AI went down dark alleys

These were AI practice failures, not missing primitives.

  • Mocked fake capabilities — Created bundle.load and session.AmplifierSession that didn't exist. The real session.spawn was there the whole time.
  • Didn't study reference implementations — The task tool showed the correct pattern. It was never consulted.
  • Asserted without verifying — "Workers are running" when spawn events never appeared in logs.
  • Then the bug cascade — status vocabulary, session storage paths, tool source paths, race conditions. Four assumptions, all wrong.
The Lesson

It wasn't a tooling problem.
It was a process problem.

session.spawn existed the whole time. The AI just never looked.

The fix isn't a better API. It's process discipline plus design investment — and the rest of this story is the proof.

Rigorous Design Validation
The Opposite of the Dark Alley

Context first, design second

Instead of assuming, the design process started by studying the existing system — and validating every proposed primitive against real code.

# Code analysis reveals the truth, before designing: grep -r "spawn_bundle" amplifier-core/src/ # No results - doesn't exist yet grep -r "EventRouter" amplifier-core/src/ # No results - needs to be built grep -r "TriggerSource" amplifier-core/src/ # No results - proposed, not implemented # Now we know exactly what needs to be built.

In Part 1, the AI assumed and mocked. Now, we looked first.

Rigorous Design Validation
The Breakthrough

The aha: agents are just inline bundles

"What if agents were never a separate concept? They're just inline bundle definitions that inherit heavily from the parent session."

Agent spawning IS bundle spawning — just with different inheritance levels. One primitive, spawn_bundle(), covers them all.

Inheritance What You Get What You Override
Full Bundle Nothing Everything — define it all yourself
Agent Provider, settings, most context Tools, specific context, instructions
Self Everything Just fork — new instance, same config
Implementation Infrastructure
The Methodology

Four pillars kept the AI on the lit path

Guardrails so the AI could work autonomously without wandering back into dark alleys.

  1. AGENTS.md — Auto-loaded context for any session in the directory. No re-explaining the project; the AI always knows the mission.
  2. Working Memory — A session-state "save game" that persists. The AI knows where it left off; no context loss between sessions.
  3. PHASE-GATES.md — Checkbox tracking with explicit criteria. The AI knows what "done" means; no subjective judgment calls.
  4. Validation Recipes — Automated PASS/FAIL verification. No "looks good" — objective gates. Trust is earned by evidence.
The Result
Autonomous Execution

Five phases, implemented autonomously

With the guardrails in place, the AI worked through every phase — implementing, testing, fixing, committing — without human intervention.

Shipped: ~1,200 lines, 11 new files, 461 tests passing, and 4 PRs merged — reusable primitives, not just a one-off Foreman.
