The Problem

One monolithic “do everything” context pollutes every agent

In a complex AI workspace, context pollution is real — every agent drags around knowledge it will never use:

Without scoping
⚠️ Root-level context knows about the whole pipeline
⚠️ The github-local agent shouldn’t need CXDB internals
⚠️ amplifier-resolve needs Docker + GitHub, not storage abstractions

Bigger windows mean slower, pricier, less accurate calls — and every agent paying for context that belongs to someone else.

The Pattern

Scope context per directory — then connect the specialists over A2A

One project. Many agents. Each with exactly the right context — and a way to talk to each other. Not a compromise; a feature.

The Trust Tier Breakthrough

Trust tiers decide it: known waits for a human, trusted runs autonomously

A2A’s trust system controls whether an incoming message needs human approval or responds on its own:

🔒 known tier

Message is queued → session enters INPUT_REQUIRED → a human must review and respond before the pipeline continues.

Pre-registered agents in known_agents start here by default.

→ A2A message received
⏸ INPUT_REQUIRED (blocked)
👤 Human reviews & responds
→ Pipeline resumes
✅ trusted tier

An autonomous child session is spawned immediately → the agent responds with no human in the loop.

Upgrade via a2a trust or a direct contacts.json edit.

→ A2A message received
⚡ Child session spawned
🤖 Responds autonomously
→ Pipeline continues
What We Learned

The one rough edge: trust can’t yet be declared up front

⚠️
known_agents in bundle.md only accepts {name, url} — no tier parameter. Pre-registered agents always land at "known", needing a separate step to elevate before autonomous comms work.
🔁
First autonomous run required a manual trust upgrade. One-time setup, but not yet declarative.
⏱
A2A timeout sensitivity — slow LLM responses in subdirectory agents can cause parent-side timeouts during pipeline runs.
Fix #1 — Direct contacts.json edit

One-time, persistent across sessions. Best for stable trusted peers.

# ~/.amplifier/a2a/contacts.json { "tier": "trusted" } // was: "known"
Fix #2 — Runtime a2a trust

Programmatic, cross-machine, scriptable. Best for CI or dynamic environments.

# At session startup: a2a(operation="trust", agent="self-improvement-agent", tier="trusted")

The ideal future: known_agents should support a tier field — trust declared once, versioned with your bundle, applied automatically at startup.
