The Enemy

LLMs reach for the same slop every time.

“AI slop” isn’t random — it’s a set of hardcoded priors. Three flavors show up in almost every generation:

🎨

Statistical Slop

Centered heroes, Inter font, purple-blue gradients, 3-column equal-width card grids, h-screen, and rounded-full on every button.

📋

Placeholder Theater

Code trails off with // ... placeholders, “for brevity” hedges, and “rest of the code here” elisions. It looks complete but isn’t.

✍️

Copy Clichés

“Elevate Your Workflow.” “Seamless integration.” “Next-gen platform.” The same startup-slop phrases, every time.

Why It’s Hard

You can’t fix taste with vibes.

“Make it look nicer” is a vibe, not an instruction. It doesn’t move a model’s hardcoded priors — the next generation looks exactly as generic as the last.

Same prompt, same model — 8 banned patterns in a single hero component: centered hero, h-screen, purple gradient, Inter font, “Elevate”, “Seamlessly”, “next-gen”, rounded-full. Vague taste requests fixed none of them.

— Before/after analysis, amplifier-bundle-taste README
The Reframe

Testable bans and parametric dials rewire the defaults — no new code.

The bundle didn’t add code paths or libraries. It replaced vague taste with named, grep-checkable rules and numeric controls, and shifted where the model starts from.

From vibes...

“Make it modern and clean” — unmeasurable, unenforceable, and quietly ignored by the model’s priors.

...to switches

Named hard bans with 5-second tests, plus three numeric dials. Every rule is checkable; every default is deliberately off the slop baseline.

Same prompt, same complexity, completely different output quality — because the model’s starting point moved, not the amount of code you wrote.

Named Bans

50+ named bans, each checkable in five seconds.

One claim: if a rule can’t be tested, it can’t be enforced. Every ban has a concrete check — grep the source or inspect the rendered page.

  • Visual bans — Inter font, purple gradients, h-screen, centered heroes, rounded-full CTAs: forbidden by name across all archetypes.
  • Copy bans — “Elevate”, “Seamlessly”, “next-gen”, placeholder brand names: no reaching for startup slop.
  • Output discipline — an always-on rule bans // ... placeholders and “for brevity” elision, defining a clean pause/resume protocol for token-limited output instead.
Each ban is a 5-second test by visual inspection or grep — verifiable, not aspirational.
Parametric Controls

Three dials act as switches, not suggestions.

One claim: global variables drive branching logic through the skill body — threshold crossings flip specific patterns on or ban them outright.

DESIGN_VARIANCE

Default: 8 · Range: 1–10

Layout symmetry → asymmetry. > 4: centered hero is banned.

MOTION_INTENSITY

Default: 6 · Range: 1–10

Hover-only → scroll-triggered reveals. > 5: magnetic micro-physics enabled.

VISUAL_DENSITY

Default: 4 · Range: 1–10

Gallery airy → cockpit dense. > 7: card containers are banned.

Defaults set to (8, 6, 4) — deliberately pushing away from the symmetric, static, card-spam baseline LLMs default to.
Aesthetic Archetypes

Four design languages overlay one shared base.

One claim: pick exactly one archetype and get a coherent dialect — palette, type stack, motion budget, and layout posture. Mutually exclusive; never compose two.

  • Minimalist (Notion / Linear) — off-white, Cabinet Grotesk + Newsreader, gradients banned, editorial restraint.
  • Brutalist (Swiss Industrial / CRT) — 90° corners, border-radius banned, monospace-heavy, high-contrast data.
  • Soft-Editorial (Ethereal Glass) — Doppelrand double-bezel, floating glass pill nav, backdrop-blur-2xl required.
  • GPT-Strict (Codex / GSAP) — XML design plan, standalone, grid-flow-dense mandatory, no cheap meta-labels.
Composition rule: base + exactly one archetype, or gpt-taste standalone (replaces the base).
Workflows

Three recipes turn taste into repeatable workflows.

A

Image-to-Code

Generate reference images → systematic visual analysis (typography, spacing, palette, anti-drift flags) → approval gate → faithful implementation. Three phase-gated stages, no simplification.

B

Design System Bootstrap

Interview the user → recommend an archetype with reasoning → approval gate → write a self-contained DESIGN.md with concrete hex codes, rem values, and conventions. One-time setup, permanent reference.

C

Redesign Audit

Scan an existing codebase against the full ban list → structured violation report with file:line citations → approval gate → targeted fixes. Upgrades projects in place, no framework migration.

One claim: image-to-code replaces a 1,228-line monolithic upstream skill with a 3-stage declarative YAML workflow — because sequential, phase-gated pipelines are recipes, not skills.
