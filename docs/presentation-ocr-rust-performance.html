The Solution

Python orchestrates; Rust does the heavy lifting

  • Python orchestration: file discovery, pattern management, reporting
  • Rust processing: CPU-intensive regex over text, via a PyO3 bridge
  • ~450 pre-compiled patterns: 150+ long-ſ, 200+ OCR fixes, 50+ watermark, 50+ misc — zero per-file compile cost
  • Rayon parallelization: all 16 cores saturated
Python baseline
• Interpreted bytecode
• Regex compiled per file
• Single-threaded (GIL)
• String copying overhead 0.4 files/sec
Rust + PyO3
• Compiled native code (~10×)
• Pre-compiled regex (~5×)
• 16-core parallelism (~2.3×)
• Zero-copy strings (~1.5×) 44.75 files/sec

Why It's Trustworthy

The ladder caught a bug that would have wrecked 1.2M words

“Wait, those are perfectly valid words. What's happening?”
— robotdad, reviewing vocabulary analysis

A Python↔Rust pattern-sync issue was flagging 1.2M false positives — caught before production. Final precision on 100K files: 99.98% (only 225 false positives out of 1,014,036 flags).

Judgment

Knowing when to stop was a data-driven call

The last 225 errors weren't fixable with regex — and Amplifier said so with evidence.

  • Random capitalization from fundamental OCR failure
  • Garbage text from completely failed scans
  • Mixed-language encoding errors and unusual proper nouns

The decision: stop adding patterns; pivot to statistical noise filtering instead of chasing diminishing returns.
