The Problem

Coordinated by hand, multi-agent workflows break

Error-prone
Complex work runs many agents in sequence. Wiring their inputs and outputs together by hand drops context and mis-orders steps.
Never the same twice
Run the same workflow again and it drifts. Without a written definition, no two runs match — and none are versioned.
Progress lost on interruption
A long run gets interrupted and there is nothing to fall back on. You start over from step one.
What a recipe is

A recipe is declarative YAML the engine runs for you

name: code-review-workflow description: Review code and deploy on approval steps: - id: analyze agent: foundation:explorer output: analysis prompt: "Analyze changes in {{file_path}}" - id: review agent: foundation:zen-architect output: review_result prompt: "Review code quality: {{analysis}}" - id: approve type: approval_gate message: "Review complete. Deploy?" - id: deploy type: bash command: "deploy.sh {{file_path}}"
Named steps, each dispatching an agent or command. You describe the workflow once; the engine executes it the same way every time.
The payoff

Interrupt at step 3 — resume with every result intact

# Recipe interrupted at step 3? Resume it: amplifier run "resume recipe session recipe_20260121_abc123" # Or list all active sessions: amplifier run "list recipe sessions" # All previous step results preserved # Context accumulation intact # Picks up at the exact step that was interrupted
The engine checkpoints after every step. Close your laptop, go to a meeting, come back and resume. The workflow stops being something you babysit and becomes an artifact you run.
Human-in-Loop

An approval gate halts the workflow for a human before it deploys

Agent: Analyze
↓
Agent: Review
↓
⏸ Approval Gate
↓ human approves
Bash: Deploy
Review before deployment, approve before destructive operations. Staged recipes group steps into phases with an approval between each stage — judgment stays human.
Context Flow

Each step's output becomes the next step's input

- id: analyze output: analysis # names this step's result - id: review prompt: "Review: {{analysis}}" # later steps read it output: review_result
A step's output becomes a named variable. Reference it later with {{variable}} and context flows forward automatically — no manual hand-off.
Control Flow

Recipes loop and branch — they don't just march in a line

Foreach + Parallel
Iterate a collection with foreach; add parallel: N to process N items at once. Ideal for multi-file analysis.
While / Convergence
Loop with while_condition until a quality threshold is met; max_iterations is the safety bound.
Conditional
Skip or route steps on conditions: skip deep validation for clean code, escalate critical findings.
Authoring

You don't hand-write recipe YAML — an agent generates it

# Describe the workflow in plain language: amplifier run "use the recipe-author agent to build a recipe that reviews a PR and deploys on approval" # The recipe-author agent emits validated YAML # Start from 46 templates in examples/
The recipe-author agent writes the YAML. You describe intent; it produces a correct, versioned recipe. Editing YAML by hand is the exception, not the rule.
