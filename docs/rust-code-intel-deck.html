Why Text Search Fails Agents

grep finds strings.
It can't tell an impl from a comment.

🔍
grep matches text, not meaning
A search for a trait returns comments, docs, and mock code as if they were real implementations. Noise, not answers.
🧩
No semantic graph
Without type information, agents can't trace call hierarchies, resolve generics, or reason about what actually connects to what.
🔄
The feedback loop is broken
Write code → shell out to the compiler → parse raw text → hope. Slow, fragile, and easy to misread.

The Payoff

goToImplementation finds every implementor.
grep literally cannot.

grep for implementors
# Find all implementors of Handler trait? $ grep -r "impl Handler" src/ src/api.rs: impl Handler for ApiHandler src/ws.rs: impl Handler for WsHandler src/test.rs: // impl Handler mock ← false positive src/doc.rs: /// impl Handler pattern ← noise # Misses: blanket impls, generic impls, # impls in dependencies, re-exports...
LSP goToImplementation
# Every implementor. Every crate. Precise. LSP.goToImplementation( "src/traits.rs", Handler ) → [ ApiHandler src/api.rs:15 WsHandler src/ws.rs:8 BatchHandler src/batch.rs:22 ProxyHandler deps/proxy/src/lib.rs:44 ] # Including blanket impls, generics, deps ✓
All trait implementors across the entire workspace — blanket impls, generic bounds, and implementations in dependency crates. This is understanding, not searching — and it's why every other operation matters.
Closing the Loop

The agent verifies its own edits compile
— through diagnostics

Before: Shell Out
# Agent writes code, then... $ cargo check 2>&1 error[E0277]: the trait bound `MyStruct: Serialize` is not satisfied --> src/main.rs:42:5 | 42 | serde_json::to_string(&val) | ^^^^^^^^^^^ the trait | `Serialize` is not | implemented # Parse raw text. Hope for the best.
After: LSP Diagnostics
# Agent writes code, then... LSP.diagnostics("src/main.rs") → [{ line: 42, severity: "error", code: "E0277", message: "trait Serialize not implemented", codeActions: ["Add #[derive(Serialize)]"] }]
One claim
Structured data, precise line numbers, and suggested fixes mean the agent checks its own work inside the LSP — no shelling out, no parsing text.
Fast Enough to Use Every Time

A warm proxy erases rust-analyzer's
60-second cold start

Indexing a large workspace takes 30–90 seconds. That's fine once — but not every session. A persistent proxy keeps the server warm so intelligence is instant.

Auto-restart on crash, idle timeout, cross-session discovery. If rust-analyzer dies the proxy re-indexes; new sessions discover the running proxy through state files. Agents never see downtime.
Beyond the Standard Operations

customRequest reaches macro expansion
no grep can see

The 14th operation is an escape hatch: send any server-specific method. For Rust that means expanding what the compiler generates — invisible to any text search.

Extensibility
expandMacro · relatedTests · externalDocs
Expand #[derive(Debug)], serde macros, and custom derives — see exactly what the compiler writes for you.
Per-language
One hatch, any server
customRequest forwards to whatever the configured language server supports — so the toolkit grows without changing the module.
How It's Built
